4. FRONTEND ARCHITECTURE (REACT + TYPESCRIPT)
================================================================================

4.1 State Management (Redux Toolkit)
------------------------------------
The frontend uses Redux Toolkit to manage centralized state across the app:
* `authSlice`:
  - Stores: `user` (profile details, role, email), `token` (JWT string), `isAuthenticated`, `isLoading`, `error`.
  - Actions: `loginSuccess`, `logout`, `updateUserProfile`, `setAuthLoading`.
  - Persistence: Persists active JWT token in `localStorage.getItem('ingage_token')`.
* `courseSlice`:
  - Manages active course catalogs, category filters, search keywords, and active course learning progress.
* `careerSlice`:
  - Asynchronously loads career pathways and job roles from `/api/careers`.
* `opportunitySlice`:
  - Asynchronously loads open internships, bounties, and full-time positions from `/api/opportunities`.

4.2 Routing Architecture, Role Guards & Access Levels
------------------------------------------------------
Navigation is coordinated cleanly via [App.tsx] with browser History API synchronization:
* Public Visitor Routes:
  - `/` (Landing Page)
  - `/courses`, `/courses/:id` (Catalog & Course Detail)
  - `/careers`, `/careers/:slug` (Career Exploration & Roadmaps)
  - `/opportunities` (Open Opportunities & Jobs)
  - `/projects` (Hands-on Capstones)

5. BACKEND ARCHITECTURE (SPRING BOOT 3 + JAVA 26)
================================================================================

5.1 Layered Architecture Pattern
--------------------------------
The backend strictly adheres to the standard 4-layer enterprise pattern:
1. Controller Layer (`@RestController`):
   - Maps HTTP endpoints, validates payload constraints (`@Valid`), enforces authorization (`@PreAuthorize`).
2. Service Layer (`@Service`):
   - Encapsulates core business transactions (`@Transactional`), manages DTO conversions, orchestrates secondary actions (logging, notifications).
3. Repository Layer (`@Repository`):
   - Extends `JpaRepository<T, ID>`, executes optimized JPQL queries, implements pagination and locking where necessary.
4. Entity Layer (`@Entity`):
   - JPA / Hibernate mapping to PostgreSQL tables. Uses optimistic locking, audit timestamps (`@PrePersist`, `@PreUpdate`), and typed enums.

5.2 Spring Security, JWT & OAuth2 Workflow
------------------------------------------
Security is configured in `SecurityConfig.java`:
* Stateless Sessions: `SessionCreationPolicy.STATELESS` ensures scalable, horizontal execution.
* Custom JWT Filter: `JwtAuthenticationFilter` reads the `Authorization: Bearer <token>` header or `AUTH_TOKEN` cookie on every incoming request.
* Claims Extracted: Subject (email), expiration timestamp, and roles.
* OAuth2 Integration:
  - Supports Google & LinkedIn OAuth2 providers via Spring Security OAuth2 Client.
  - Upon successful provider verification, `CustomOAuth2UserService` looks up or registers the user and redirects to `/oauth/callback?token=<jwt>`.

5.3 Transaction Boundaries & Hibernate Session Management
---------------------------------------------------------
* All database mutation methods are explicitly protected by `@Transactional`.
* Read-only methods (e.g. `getAllProjectsAdmin()`) use `@Transactional(readOnly = true)`.
* Element collections (e.g., `whatYouWillBuild`, `techStack`) are configured with `@BatchSize(size = 25)` to eliminate LazyInitializationException and prevent N+1 query storms.

5.4 Global Exception Handling & Error Standard
----------------------------------------------
`GlobalExceptionHandler` captures exceptions across all controllers:
* `ResourceNotFoundException` -> HTTP 404 (Entity not found)
* `MethodArgumentNotValidException` -> HTTP 400 (Field validation errors mapped to key-value pairs)
* `IllegalArgumentException` / `IllegalStateException` -> HTTP 400 (Business logic rejections)
* `AccessDeniedException` -> HTTP 403 (Insufficient permissions)
* Uncaught `Exception` -> HTTP 500 (Detailed trace logged; clean response returned to client)

7. CORE FUNCTIONAL WORKFLOWS & DATA FLOWS
================================================================================

7.1 Authentication, OTP & Email Verification Flow
------------------------------------------------
1. Registration:
   - Learner inputs name, email, password.
   - Password is encrypted with BCrypt (strength 10).
   - Account record created in `users` with `is_email_verified = false`.
   - Verification token created in `otp_verifications` (5-minute expiry).
   - Backend dispatches verification link / OTP to learner's email.
2. Verification:
   - Learner enters OTP on `/verify-otp` or clicks `/verify-email?token=...`.
   - Backend marks token as used, updates `users.is_email_verified = true`.
   - Welcome email dispatched.
3. Login:
   - Verifies credentials against BCrypt hash.
   - Enforces `is_email_verified == true`.
   - Generates signed JWT Bearer Token (24h validity).
   - Returns user metadata (ID, Name, Email, Role) to Redux store.

7.2 Secure Video Streaming & Piracy Deterrence Pipeline
-------------------------------------------------------
1. Chunked Streaming:
   - Video requested via `GET /api/courses/{courseId}/lessons/{lessonId}/stream`.
   - Server verifies caller is enrolled or lesson has `is_free_preview = true`.
   - Controller parses HTTP `Range: bytes=start-end` header.
   - Streams requested byte range with `HTTP 206 Partial Content` and `Content-Range`.
2. Client-Side Piracy Deterrence:
   - Right-click and context menu blocked on video viewport.
   - Keyboard shortcuts (`Ctrl+S`, `Ctrl+U`, `F12`, `PrintScreen`) intercepted.
   - Dynamic, randomized floating watermark overlays learner's Email, User ID,
     and active UTC timestamp every 15-30 seconds across the screen.

7.3 Razorpay Payment, Webhook Verification & Enrollment Provisioning
--------------------------------------------------------------------
1. Order Initiation:
   - Client calls `POST /api/payments/razorpay/create-order` with course ID.
   - Backend calculates final price (applying coupon if present) and invokes Razorpay API.
   - Creates a pending record in `payments`.
2. Client Checkout:
   - Razorpay Checkout modal loads with Order ID, Amount, Currency (INR).
   - Learner completes UPI, Card, NetBanking, or Wallet payment.
3. Signature Verification & Auto-Provisioning:
   - Client submits `razorpay_order_id`, `razorpay_payment_id`, and `razorpay_signature`
     to `POST /api/payments/razorpay/verify`.
   - Backend computes HMAC-SHA256 signature using `razorpay.key.secret`.
   - If signature matches:
     * Sets `payments.status = CAPTURED`.
     * Creates `enrollments` record with status `ACTIVE`.
     * Sends payment confirmation email.
     * Returns success redirect payload.

7.4 PDF Certificate Generation & Verification Engine
----------------------------------------------------
1. Eligibility Check:
   - Learner reaches 100% completion in `lesson_progress` and passes final quiz.
2. Dynamic PDF Synthesis (OpenPDF):
   - Certificate record generated with unique UUID verification code.
   - Vector graphics engine renders certificate border, Ingage LMS gold seal,
     student name, course title, completion date, and verification QR/URL.
3. Public Credential Verification:
   - Any employer or visitor visits `/certificate/verify/{code}`.
   - Calls public endpoint `GET /api/certificates/verify/{code}`.
   - Displays authenticated badge, issue date, recipient name, and PDF download button.

7.5 Projects & Capstone Engine
------------------------------
1. Explore:
   - Public visitors browse projects by industry (Healthcare, Gaming, FinTech, EdTech).
   - Fetched strictly via `GET /api/projects` from PostgreSQL.
2. Enroll & Complete:
   - Authenticated learners initiate a capstone project.
   - Access blueprints, tech stacks, and step-by-step objectives.
   - Complete project submissions and earn verified skills badges.

7.6 Admin Control Plane & Activity Audit Logging
------------------------------------------------
1. Unified Dashboard:
   - Real-time KPI counters: Total Students, Total Revenue, Active Enrollments, Completion Rates.
2. Complete Resource Management:
   - Courses: Add, edit, publish/unpublish, reorder lessons, inspect student analytics.
   - Users & Instructors: View profiles, edit roles, toggle active/ban status.
   - Commerce: Real-time payment logs, coupon generator, refund handling.
3. Immutable Audit Trail:
   - Every administrative modification (publish, status toggle, delete, role change)
     is automatically recorded in `admin_activity_logs` with admin username,
     IP address, timestamp, and action description.

AUTH & USERS
  POST /api/auth/register                   Register new account
  POST /api/auth/login                      Login with email + password

  POST /api/auth/logout                     Invalidate session / clear cookie
  GET  /api/users/me                        Get current user profile
  PUT  /api/users/me                        Update profile details (name, phone)

  POST /api/enrollments/{courseId}/lessons/{lessonId}/complete  Mark lesson finished
  POST /api/quizzes/{quizId}/submit         Submit quiz answers & get instant score

PAYMENTS & COMMERCE
  POST /api/payments/razorpay/create-order  Initialize Razorpay order

  GET  /api/payments/my                     Get learner transaction receipts

CERTIFICATES
  GET  /api/certificates/my                 Get current user's certificates

  GET  /api/admin/certificates              Inspect issued credentials
  GET  /api/admin/activity-logs             Query immutable administrative audit log
  GET  /api/admin/settings                  Get platform system settings
  PUT  /api/admin/settings                  Update platform system settings
